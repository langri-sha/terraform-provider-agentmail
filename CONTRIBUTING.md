# Contributing

Bug reports and pull requests are welcome. Please open an issue first to discuss
major changes. The only hard rules:

- All Go code passes `go vet ./...` and `go test -race ./...`.
- All Terraform examples pass `terraform fmt -check -recursive examples`.
- `docs/` matches what `scripts/generate-docs.sh` renders.
- Commit subjects are plain imperative sentences, without type prefixes.

## Layout

```
.
├── cmd/terraform-provider-agentmail/   # provider entrypoint (main.go)
├── internal/
│   ├── agentmail/                      # HTTP client for AgentMail's API
│   ├── fakeagentmail/                  # in-memory AgentMail for tests, with contract tests
│   │   └── testdata/openapi.yml        # vendored OpenAPI document
│   └── provider/                       # plugin-framework provider and resources
├── examples/                           # rendered into docs/
├── docs/                               # generated by scripts/generate-docs.sh
├── scripts/generate-docs.sh            # regenerate docs/ with tfplugindocs
├── scripts/update-openapi.sh           # re-vendor AgentMail's OpenAPI document
├── .goreleaser.yml                     # GoReleaser build and signing config
└── .github/workflows/                  # CI and release
```

## Development

```sh
go mod tidy
go vet ./...
go test ./...
```

The tests drive Terraform itself, so they need `terraform` on `PATH`; CI pins
the version in `.github/workflows/test.yml`. To run examples against a local
build, see [`examples/README.md`](./examples/README.md) for the `dev_overrides`
workflow. Regenerate `docs/` with `scripts/generate-docs.sh` whenever the
schema or examples change.

## Releasing

The provider is meant for the public Terraform Registry as
`langri-sha/agentmail`. Releases are cut from the GitHub UI and built by CI:

1. Update `CHANGELOG.md` for the new version.
2. Publish a GitHub Release for the `vX.Y.Z` tag, writing the release notes there.
3. The [`Release`](./.github/workflows/release.yml) workflow runs GoReleaser
   ([`.goreleaser.yml`](./.goreleaser.yml)): it builds the cross-platform
   archives, generates and GPG-signs `SHA256SUMS`, and attaches them, plus
   `terraform-registry-manifest.json`, to the release. The registry ingests it.

Publishing relies on one-time setup outside the repo. The signing key's public
half is registered on the langri-sha registry namespace, and `GPG_PRIVATE_KEY`
is an Actions secret; `PASSPHRASE` is needed only when the key has a
passphrase. The provider is published on the registry once, after the first
GitHub release exists, because the registry needs a release to publish.
